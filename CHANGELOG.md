# Changelog

## 2026-08-15

### Исправлено
- **Закрыта мина невоспроизводимых зависимостей.** `requirements.txt` содержал
  `python-telegram-bot>=20.0` (верхней границы нет — следующий мажор приедет сам)
  и `requests` / `python-dateutil` вообще без версий. Каждая пересборка образа
  тянула свежие релизы, то есть была апгрейдом вслепую: несовместимость всплыла бы
  не в CI, а в проде. Прямые зависимости прибиты точными версиями.
- **Утечка в образ: `COPY . /app` тащил в образ `.git`, а боевой `.env` с
  токенами утащил бы следом.** `.dockerignore` в репозитории не было, а
  `.gitignore` на Docker-контекст не влияет — найдено при ревью. Добавлен
  `.dockerignore` (env-файлы, `.git`, `sessions/`, `tdatas/`, `*.session`,
  байткод). Проверено: `.git` из собранного образа исчез.
  ⚠️ Опубликованный образ `ghcr.io/stufently/avia-search-bot:latest` от
  2026-06-25 содержит `.git` этого репозитория — секретов там нет (`.env`
  никогда не коммитился), но образ стоит перевыпустить.

### Добавлено
- `constraints.txt` — полный слепок работающего окружения, включая транзитивные
  пакеты (`httpx`, `httpcore`, `anyio`, `urllib3`, `certifi`, `idna`, `h11`,
  `six`, `typing_extensions`, `charset-normalizer`). Без него класс проблемы
  закрыт наполовину: прямые пины не мешают транзитивным разъезжаться.
  Версии взяты из `pip freeze` образа `ghcr.io/stufently/avia-search-bot:latest`
  (сборка 2026-06-25, commit 2885963) — это то, что реально работало, а не
  «последнее доступное».
- `verify_pins.py` — проверка воспроизводимости: каждая строка `requirements.txt`
  обязана быть точным пином, а каждый установленный пакет обязан совпасть со
  слепком. Закрывает дыру, которую `pip check` не видит: новая незапиненная
  (в том числе транзитивная) зависимость теперь валит сборку, а не приезжает
  молча.
- **Гейт зависимостей в `Dockerfile`** (финальный этап): `python -m pip check`,
  затем `verify_pins.py`, затем явный импорт ключевых библиотек, затем
  построение приложения `bot.build_application()` с фиктивным токеном.
  Построение — не то же самое, что импорт: несовместимость СИГНАТУР
  (`HTTPXRequest`, цепочка `ApplicationBuilder`) видна только при фактическом
  создании объекта. Сеть не трогается, она начинается в `run_polling()`.
  Гейт исполняется внутри `docker/build-push-action` в
  `.github/workflows/ci.yml`, то есть в том же workflow, что публикует образ
  в GHCR — сломанный образ до `:latest` не доедет.
  Проверено негативно, четырьмя способами: (а) подсунутый `httpx==0.24.1` —
  падение на `pip check`; (б) битый импорт в `bot.py` — падение на импорте
  приложения; (в) лишний незапиненный пакет в образе — падение на
  `verify_pins.py`; (г) прежний, «дырявый» `requirements.txt` с `>=` и голыми
  именами — тоже падение на `verify_pins.py`.
- Базовые образы в `Dockerfile` прибиты по digest (`python:3.12.9-slim@sha256:48a11b7b…`):
  даже точный тег мутабелен и может быть перевыпущен.
- `.env.example` — шаблон переменных окружения (`TELEGRAM_TOKEN`, `API_TOKEN`),
  которые читает код (`bot.py`, `search_flights_text.py`) и требует
  `docker-compose.yml` через `env_file`. Раньше шаблона не было вовсе, а README
  ошибочно предлагал вписывать токены прямо в `.py`-файлы.

### Изменено
- `bot.py`: сборка `Application` вынесена из `main()` в `build_application()`.
  Поведение не изменилось (`main()` строит и запускает polling) — вынос нужен,
  чтобы гейт сборки мог построить приложение, не поднимая polling.

### Известные ограничения (осознанно не чинили)
- Версии системных пакетов apt (`libglib2.0-0`, `gcc`, `build-essential`,
  `python3-dev`, `git`) не пинятся: в Debian slim конкретные версии со временем
  пропадают из репозитория и пин ломает сборку целиком. Риск принят.
- `runs-on: ubuntu-latest` и GitHub Actions по мажорным тегам (`checkout@v7`
  и т.д.) тоже плавают. Пин по commit SHA — отдельная задача supply-chain, в
  этот заход не входила.
- `docker-compose.yml` тянет `ghcr.io/stufently/avia-search-bot:latest`, а README
  предлагает `docker-compose pull`. Для воспроизводимого деплоя стоит
  переключиться на тег по SHA коммита (workflow публикует и его). Решение за
  владельцем: compose описывает целевой хост, а не сборку. Смягчено тем, что
  теперь сломанный образ до `:latest` просто не доезжает — гейт валит сборку.
