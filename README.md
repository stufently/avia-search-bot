# avia-search-bot

Простой набор скриптов для поиска авиабилетов:

1. **search_flights_text.py** — CLI‑инструмент для поиска по API Aviasales (Travelpayouts).  
2. **bot.py** — Telegram‑бот, обёртка над CLI: отвечает на текстовые запросы.

## Требования

- Python 3.12 (образ собирается на `python:3.12.9-slim`, прибитом по digest)
- Зависимости — только из файлов репозитория, версии зафиксированы:

    ```bash
    pip install -r requirements.txt -c constraints.txt
    ```

  `requirements.txt` — прямые зависимости с точными версиями.
  `constraints.txt` — полный слепок окружения, включая транзитивные пакеты.
  **Не ставить пакеты в обход этих файлов** — ни `pip install <пакет>` без
  версии, ни `pip install -U`: любая установка мимо слепка делает пересборку
  апгрейдом вслепую.
  Поднимать версии — осознанно и вместе: правка обоих файлов → пересборка образа
  → гейт в `Dockerfile` должен пройти.

## Настройка

Токены читаются из переменных окружения, в код их вписывать не нужно.
Скопируйте шаблон и заполните:

```bash
cp .env.example .env
```

| Переменная | Где читается | Что это |
|---|---|---|
| `TELEGRAM_TOKEN` | `bot.py` | токен бота от @BotFather |
| `API_TOKEN` | `search_flights_text.py` | токен Travelpayouts (Aviasales) |

## Запуск

### Telegram‑бот
    python3 bot.py

В Telegram отправьте боту, например:
    Париж Лондон на 5–10 дней в одну сторону

### Гейт зависимостей в сборке

Финальный этап `Dockerfile` прямо во время сборки:

1. `pip check` — конфликты версий в установленном дереве;
2. `verify_pins.py` — все строки `requirements.txt` точные пины, все
   установленные пакеты совпадают с `constraints.txt` (новая незапиненная
   зависимость валит сборку);
3. импортирует ключевые библиотеки;
4. строит приложение `bot.build_application()` с фиктивным токеном — импорт
   не поймает несовместимость сигнатур, построение поймает. Polling не
   запускается, сеть не трогается.

Несовместимая библиотека валит **сборку**, а не прод: до тега `:latest` в GHCR
сломанный образ не доезжает. Гейт исполняется и локально (`docker build`), и в
`.github/workflows/ci.yml` — том же workflow, что публикует образ.

Если добавляете библиотеку, которая не втягивается боевой цепочкой импорта,
допишите её явным импортом в этот `RUN`, иначе гейт её не проверит.

### Контекст сборки

`.dockerignore` держит вне образа `.git`, любые `.env` и рабочие каталоги
(`sessions/`, `tdatas/`). `.gitignore` на Docker-контекст **не влияет** — без
этого файла боевой `.env` с токенами уехал бы в образ.
